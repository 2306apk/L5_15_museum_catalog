# Static Code Analysis Issue Documentation

## Overview
This document records the issues identified during static code analysis of `museum_catalog.py` using Pylint, Bandit, and Flake8, along with the corrective actions taken.

## Issue Table

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| SQL Injection Vector via String Concatenation (`B608`) | Security | 11 | The `addArtifact` function constructed an `INSERT` statement using raw string concatenation with `title`, `era`, `value`, and `on_display`. This allows SQL injection if untrusted inputs contain single quotes or malicious SQL syntax. | Replaced string concatenation with parameterized query placeholders (`?`) executed as `(?, ?, ?, ?)` and added type and range validation for inputs. |
| Hardcoded Sensitive Password (`B105`) | Security | 7 | The script declared `CURATOR_PASSWORD = "m4seum!"` directly in source code. Storing plaintext credentials in version control poses security risks of credential theft and unauthorized access. | Removed the unused hardcoded password constant from the module. |
| Insecure Subprocess Call with `shell=True` (`B602`, `B607`, `B404`) | Security | 3, 37 | `backupNote` used `subprocess.call("echo catalog backup complete", shell=True)` with a partial path and shell invocation, opening risks to shell injection and platform discrepancies. Bandit also flagged `import subprocess`. | Replaced the subprocess call with standard Python `print("catalog backup complete")` and eliminated `import subprocess`. |
| Unhandled Missing Artifact Crash (`TypeError`) | Bug | 16–17 | `displayStatus` immediately indexed `row[0]` on the result of `fetchone()`. When an artifact ID does not exist, `fetchone()` returns `None`, raising an unhandled `TypeError: 'NoneType' object is not subscriptable` and crashing the program. | Added a `None` check on `row` returning a descriptive message (`f"artifact {artifact_id} not found"`) before accessing row attributes, along with integer validation for `artifact_id`. |
| Unused Function Parameter (`W0613`) | Code Quality | 15 | In `def displayStatus(artifact_id, curator):`, the parameter `curator` was accepted but never used in the function body, cluttering the API signature. | Provided a default value `curator="Unknown"`, documented the parameter in the docstring for catalog audit tracking, and referenced `curator` internally to retain backwards compatibility without unused warnings. |
| Unused Import Statement (`W0611`, `F401`) | Style / Maintainability | 2 | `import datetime` was declared at the top of the file but was never referenced anywhere in the script, causing unnecessary overhead and namespace pollution. | Removed the unused `import datetime` line. |
| Non-conforming Function Identifiers (`C0103`) | Style | 10, 15, 24, 31, 36 | Function names (`addArtifact`, `displayStatus`, `totalValue`, `moveToDisplay`, `backupNote`) used camelCase instead of PEP 8 snake_case format. | Renamed functions to snake_case (`add_artifact`, `display_status`, `total_value`, `move_to_display`, `backup_note`) and updated invocations in `main()`. |
| Unnecessary Else Block After Return (`R1705`) | Code Quality | 17–20 | `displayStatus` had an `else` branch immediately following a `return` statement, creating redundant indentation and violating clean code practices. | Removed the redundant `else` block and unindented the fallback return statement to the outer function level. |
| Formatting, Spacing, and Line Length Violations (`E501`, `E225`, `E303`, `C0301`) | Style | 6, 11, 16, 24, 25, 26, 32 | Multiple lines exceeded 79 characters (up to 158 characters in Line 11), missing whitespace around operator (`total=0`), and three blank lines instead of two between top-level functions. | Re-formatted SQL queries into multi-line strings, added spaces around operator (`total = 0`), and normalized blank lines to standard PEP 8 spacing (two blank lines between functions). |
| Missing Module and Function Docstrings (`C0114`, `C0116`) | Maintainability | 1, 10, 15, 24, 31, 36, 40 | Neither the module nor the individual functions contained explanatory docstrings describing their purpose, parameters, and return types. | Added standard docstrings to the module header and each function defining behavior and expected types. |
| Missing Main Module Execution Guard | Maintainability | 50 | `main()` was executed unconditionally at the root of the file, causing demonstration code to execute automatically whenever the file was imported. | Placed the execution of `main()` inside the standard `if __name__ == "__main__":` guard. |
